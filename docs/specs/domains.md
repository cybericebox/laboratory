# Домены лабораторий и регионы

## Сейчас: один кластер

Все три имени задаются только конфигурацией (env, values чарта). В коде нет ни значений по умолчанию, ни склейки из зоны: без них сервисы не стартуют. Ниже — значения локального стенда.

| Имя | Куда | Что |
|---|---|---|
| `*.labs.<zone>` | L7-прокси | веб-доступ к устройствам лабораторий |
| `vpn.<zone>` | WireGuard-демультиплексор | VPN участников и авторов |
| `ctl.<zone>` | агент laboratory (gRPC, mTLS) | служебное имя для бэкенда платформы |

Хост веб-устройства: `<device>-<code>.labs.<zone>`, например `web-only-x7q.labs.cybericebox-dev.pp.ua`.

- `<device>` — имя устройства из топологии, не длиннее 35 символов.
- `<code>` — 3 случайных символа `[a-z0-9]`. Оператор создаёт Service с именем `<device>-<code>` в namespace группы. Уникальность внутри группы гарантирует Kubernetes: если имя занято, берётся другой код. После 8 конфликтов код становится 4-символьным, длиннее не бывает.
- Прокси берёт группу из токена сессии, а метку хоста — как имя Service в namespace этой группы. Ни индекса, ни хранимого счётчика нет.
- Почему `labs`, а не `challenges`: в хосте сидит устройство лаборатории, а не задание. Одно устройство может обслуживать несколько заданий.

## Потом: несколько кластеров (регионы)

Регионы сейчас не вводятся. Когда появится второй независимый кластер, каждый кластер получает код региона и свой поддомен:

```
<device>-<code>.labs.<region>.<zone>
vpn.<region>.<zone>
ctl.<region>.<zone>
```

Пример: `web-only-x7q.labs.k1.cybericebox-dev.pp.ua`.

- Регион не может быть частью метки устройства: wildcard-запись DNS и wildcard-сертификат покрывают один уровень и указывают на один кластер. Поэтому регион — отдельный уровень домена.
- Выбран вариант «регион — поддомен кластера» (а не `labs-<region>` и не `<region>.labs`): всё, что относится к кластеру, лежит под `<region>.`. Этот поддомен можно целиком отдать кластеру (свои записи DNS, свой сертификат `*.labs.<region>`).
- Код региона — 2 символа `[a-z0-9]` (36 × 36 = 1296 кластеров). Его не вычисляют, а назначают при установке кластера (`REGION` в kit), платформа хранит его вместе с агентом. Рекомендуется буква места и цифра номера: `k1` — первый кластер в Киеве, `f2` — второй во Франкфурте.
- При переходе на регионы текущий кластер получает свой код, и его имена меняются (`labs.` → `labs.<region>.` и т. д.). Уже выданные VPN-конфигурации и ссылки перестанут работать, поэтому переход делать между заходами.
